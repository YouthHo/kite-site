部署与分享指南

KITE-SITE · 让任何人通过浏览器访问

先决条件：构建产物

dist/ 目录

项目根目录执行 npm run build 后生成 dist/（纯静态文件：index.html + assets）。本次已验证构建成功，共 20 个文件。以下所有方案本质上都是把 dist/ 放到一个公网可达的地方。

方案一：局域网分享（同一 Wi-Fi 最快）

无需联网 · 局域网内其他人可访问 
npm run preview -- --host

终端会打印类似 http://192.168.x.x:4173/ 的地址，把局域网 IP 发给同一网络下的朋友即可打开。注意：对方必须和你连同一个路由器/Wi-Fi；手机访问时确保手机没开流量隔离。

方案二：临时公网链接（分享给不在同一网络的人）

10 分钟搞定 · 链接有效到进程结束

先起本地服务，再套一层内网穿透，得到一条任何人都能打开的 https 链接。

# 终端 1：启动本地服务
npm run preview

# 终端 2（任选其一）：
npx localtunnel --port 4173          # 免费，输出 https://xxx.loca.lt
cloudflared tunnel --url http://localhost:4173   # Cloudflare 免费，输出 https://xxx.trycloudflare.com

localtunnel 首次打开会要求输入隧道密码（终端里会打印）；cloudflared 需要先安装（winget install cloudflare.cloudflared）。进程关闭链接即失效，适合临时给朋友看。

方案三：正式上线（长期稳定 · 推荐）

免费 · 永久链接 · 项目已内置配置文件

Vercel（最快，约 5 分钟）

  1. 把 kite-site/ 推到 GitHub（或直接拖拽部署：vercel.com → New Project → 上传目录）
  2. vercel.com 用 GitHub 登录 → Add New Project → 选择仓库
  3. Framework 选 Vite，Build Command npm run build，Output dist，其余默认 → Deploy
  4. 完成，获得 https://xxx.vercel.app 链接，直接发给任何人

项目里的 vercel.json 已配好 SPA 路由回退和静态资源缓存，无需再改任何东西。

Netlify（同样免费）

  1. 推送 GitHub 后，app.netlify.com → Add new site → Import an existing project
  2. Build command: npm run build；Publish directory: dist
  3. Deploy 后得到 https://xxx.netlify.app

netlify.toml 已内置同样配置。

GitHub Pages（免费，需小改动）

  1. 把 dist/ 内容推到 gh-pages 分支，或 Settings → Pages → 选分支部署
  2. 注意：GitHub Pages 默认路径是 /仓库名/，需要把 vite.config.js 的 base 改为 '/仓库名/' 后重新 build

方案四：自有服务器 / 云主机

需要一台服务器（阿里云/腾讯云/VPS） 
# 本地构建后上传 dist/ 到服务器
scp -r dist root@你的服务器IP:/var/www/kite
# 服务器 nginx 配置（/etc/nginx/conf.d/kite.conf）
server {
  listen 80;
  server_name 你的域名或IP;
  root /var/www/kite;
  index index.html;
  location / { try_files $uri $uri/ /index.html; }
  location /assets/ { expires 1y; add_header Cache-Control "public, immutable"; }
}

重启 nginx 后即可访问。有域名就解析 A 记录到服务器 IP；没域名直接用 IP 访问（80 端口需在云厂商安全组放行）。

部署后建议检查

事项说明
sitemap / robots把 public/sitemap.xml 和 robots.txt 里的 kite.example.com 替换成你的真实域名后重新 build
字体加载当前字体走 Google Fonts，国内网络可能加载慢；正式站建议把 Noto Serif SC 字体文件自托管到 public/fonts/
占位图图片全部为 picsum.photos 占位，国内访问可能较慢，正式上线前按 README 的替换指南换成本地图
页面刷新 404history 路由在静态托管上必须配置回退（Vercel/Netlify 已内置，Nginx 见上文 try_files）

最省事的推荐组合

临时分享 → cloudflared 隧道；正式上线 → Vercel（拖拽或连 GitHub 导入，免费、带 HTTPS、全球 CDN）。整个流程不需要懂服务器。
