Vercel 构建失败 · 修复记录

2026-08-09 · 提交 5b8b46b

现象

本地 npm run build 成功，Vercel 部署日志在 transforming... 阶段中断，仅有 Sass legacy-js-api 弃用警告，无明确报错即失败。

根因：文件名字母大小写不一致（跨平台经典坑）

项目源码里 import 全部是驼峰写法（@/views/HomeView.vue、@/components/NavBar.vue、./App.vue），但落盘与 git 索引中的 26 个 .vue 文件名全是小写（homeview.vue、navbar.vue、app.vue）。

Windows 文件系统不区分大小写 → 本地构建照常解析通过；Vercel 的 Linux 文件系统严格区分大小写 → Rollup 找不到 HomeView.vue，构建失败。这是"本地能跑、线上必挂"的典型场景。

修复内容

文件说明
src/app.vue → App.vue入口组件
src/views/*.vue（9 个）HomeView / GraphView / CharactersView / CastView / EpisodesView / TimelineView / ArchitectureView / HistoryView / ScenesView
src/components/*.vue（16 个）NavBar / Footer / SearchModal / ProgressSetting / BackToTop / FilmGrain / ScanLine / LoadingScreen / PageTransition / CharacterCard / EpisodeCard / QuoteCard / TimelineNode / SpoilerGuard / ShareButton / ImageLightbox
vite.config.js新增 css.preprocessorOptions.scss.api: 'modern'，消除 Sass legacy-js-api 弃用警告

共 26 个文件通过两步 git mv 完成大小写修正（Windows 上直接改名会因大小写不敏感而无效），随后本地重新构建通过（12.6s，无警告），已推送 GitHub（91cd1f5..5b8b46b），Vercel 自动重新部署。

追加：第二次修复（2026-08-09 下午）

第一次修复推送后 Vercel 仍失败，错误：Could not resolve "./app.vue" from "src/main.js"。根因：创建文件时写文件环境把路径规范成了小写，src/main.js 内容里的入口引用也变成了 import App from './app.vue'；上一轮只改了 26 个文件名，漏了文件内容里的这一行。

修复：改为 import App from './App.vue'；并新增 scripts/check-case.cjs（模拟 Linux 大小写敏感解析，扫描全部 import 与文件名比对），挂到 package.json 的 prebuild，本地与 Vercel 每次构建前自动执行，不通过即拒绝构建，杜绝同类问题复发。提交 558fe35、e345ab3。

经验清单（防止复发）

① 新建 Vue 组件/页面时，文件名首字母大写（SFC 惯例），import 路径与文件名逐字符一致；

② 提交前执行 git ls-files | findstr /i "homeview navbar" 之类检查，或直接在本机用 Linux 容器/CI 验证构建；

③ 本项目校验命令：本地构建通过 ≠ 线上通过，凡涉及新增文件必须核对 git 索引中的大小写；

④ 日志中的 lucide-vue-next 弃用提示（官方改名 @lucide/vue）仅为警告，不影响构建，可后续统一替换。
